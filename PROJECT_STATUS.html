1 · What this project is

The immediate objective is not to replace or redesign every company information system. It is to replace the current practice of sharing company documents through WhatsApp with a structured internal document platform.

The first version gives authorized team members a clean, minimalist internal environment where they can log in, upload and store documents, organize and view their own documents, invite team members, and grant access to individual documents. Product documents, updates and i363 materials are expected to be among the initial document types.

RAG remains an important part of the broader vision. The platform is modular so that document management, AI/RAG and future features can be added as pluggable modules rather than requiring the whole application to be rebuilt.

Why Supabase rather than Neon + Clerk

Bishop recommended Neon, and specifically said he likes it. The decision taken — by the project, 19 August — is to stay on Supabase for the database, authentication and file storage. The reasoning, since it runs against a direct recommendation:

ConsiderationWhy it points to Supabase
Neon is only a database Neon hosts Postgres and nothing else — no authentication, no object storage. Adopting it means Neon and Clerk and an object store: three vendors, three bills and three outage modes replacing one. The two subsystems it would replace, auth and storage, are the two that are already finished and working.
Both are the same database Neon and Supabase are both PostgreSQL. Same engine, same SQL, same pgvector. Choosing Supabase gives up none of what Bishop was pointing at — the Postgres-plus-pgvector direction he described is exactly what is running.
The substance of his advice is already implemented Bishop's actual instruction was that records should port "in a modular or dynamic way from one database to the next." That is built: db/portable-schema.sql runs on Neon unchanged, and the export/import scripts move every record in three commands. His advice was about not being trapped, and honouring it means keeping the exit proven — not taking it immediately.
Timing Nothing on this page has been verified against a live database. Migrating first would spend roughly three days rewriting the data and auth layers before knowing whether the platform works at all — and those three days cost the same whenever they are spent.

What would reverse this. An AIC policy against storing company documents with a US-hosted vendor outranks everything above, and would also decide the open LLM question. Outgrowing the free tier would prompt a re-pricing, not a re-architecture. Neither has happened; if either does, the move is the three commands in db/README.md rather than a rewrite — which is the whole point of having built it that way.

Why permissions sit in the database

The document_chunks table — which Week 2's RAG will read — carries a policy calling can_read_document. A user therefore cannot receive an answer grounded in a document they are not allowed to open, even if the retrieval code forgets to filter. Plan §6.4 is satisfied by construction rather than by discipline.

5 · RAG pipeline

Document → Extract → Clean → Chunk → Contextualise → Embed → Store → Retrieve → Generate → Cite
StageDecision takenWhy
Extract unpdf for PDF, mammoth for DOCX, a small OOXML reader over fflate for XLSX and PPTX, native for text formats. All run in-process with no external binaries, so the parser set deploys anywhere Node does. PDF extraction is per page, which is what lets a citation name a page.
Chunk ~3200 characters, 400 of overlap, split paragraph → sentence → hard, never spanning a page. Characters rather than tokens: tokenising during ingestion would mean a network round trip per document. A chunk spanning two pages could not honestly cite either of them.
Embed text-embedding-3-small, behind a provider interface. Its native 1536 width matches the column the schema already commits to. A provider with a different width needs a migration and a full re-index, not a config change.
Store pgvector with an HNSW index, in the same database. A separate vector store would add an operational component and a second permission model — which is exactly the risk this design exists to avoid.
Retrieve Hybrid: vector similarity plus a keyword arm, both through SECURITY INVOKER functions. Vector search alone misses exact identifiers like “i363”, whose embedding neighbourhood carries no signal about the literal string.
Generate Claude Opus 5, streamed, with a server-side refusal fallback. Needs Bishop The one point at which document content leaves AIC's control.
Cite Numbered [n] citations rendered as links to the source document and page, plus a source list under each answer. An answer that cannot be checked is worth less than one that can. When nothing relevant is retrieved, the system says so rather than guessing.

Full reasoning, including what is still open, is in src/modules/rag/README.md. The largest gap is OCR: a scanned document with no text layer indexes to zero passages and reports as much.

Phase 5 — Team Communication (design agreed 20 August in Documentation/TEAM_COMMUNICATION.md; reconciled with the original messaging foundation by migrations 0012–0013)
One rule holds the whole design up: a message can never carry a file. This platform exists because documents in WhatsApp could not be found, controlled or withdrawn. A chat that accepts attachments rebuilds exactly that, one layer further in. A message may reference a document and never contain one, so sharing a file still means uploading it — which means it acquires an owner, permissions, tags and an index whether the sender was thinking about that or not.

A Team is a group of people, not just a room. Slack keeps channels and user groups apart; at twelve staff that is bureaucracy, so here they are one object with an open/closed visibility setting. The document-anchored half of chat already shipped as comments (migration 0007) and stays its own table: comments hang off a document, team messages off a team, and one shared table would need a policy branching on parent type — which is where permission bugs breed.
The earlier divergence is reconciled in code. Migration 0012 evolves the existing message store into durable Direct and Team kinds with open/closed visibility, fixed two-person DMs and separate metadata/content authority. Migration 0013 adds Team document grants whose effect follows current membership. Both remain pending deployment; no second message or permission store was introduced.
Teams: create, add members, visibilityBuiltMigration 0012 adds named Teams with purpose and open/closed visibility, creation, joining and governed membership. Open Teams are discoverable and readable by active staff; closed Teams are hidden from ordinary non-members. The staff directory is now People at /admin/people, with permanent redirects from the old routes. A participant can title and tag a full conversation snapshot, which becomes a normal private-bucket Markdown document owned by the promoter and enters the existing ingestion/indexing pipeline. Team promotions atomically grant Viewer access to the Team; Direct promotions stay owner-only because a DM is never a permission group. The snapshot preserves authors, timestamps, reply ancestry, edits and retraction tombstones, omits permission-sensitive document-reference cards, and neutralizes message Markdown/HTML. The same migration closes a discovered storage-binding and Editor ownership-escalation gap with a database trigger. Built and tested, and its migration is applied to Supabase as of 1 September; the browser flow is still unverified.
Conversations in AI retrievalBuiltAsk retrieves accessible Team messages below document passages and cites them distinctly. DMs are excluded both from embedding and from semantic/keyword retrieval. Open-Team messages are readable and retrievable by active staff; closed-Team messages only by participants. Visibility changes require no destructive re-index because every retrieval call re-evaluates the Team’s current visibility under RLS, so existing embeddings become unreachable immediately when a Team closes.
Retention: nothing is ever deletedBuiltMigration 0011 removes both the hard-delete RLS policy and the authenticated Data API privilege. Ordinary users can no longer erase message rows. Retraction preserves the record and conversation shape while hiding retained content from ordinary participant queries; participant and outsider roles were exercised in the hosted rollback rehearsal. A future lawful erasure remains a separately authorised administrative operation, not an everyday message action.
Retract and version, never hard-deleteBuiltSenders can edit and retract from the conversation UI. Every edit appends the prior body to immutable version history, stamps edited_at, clears the stale embedding and schedules re-embedding. Retraction stores the final body for audit, replaces the ordinary row with a tombstone, clears its embedding, hides retained versions from participants and is irreversible through the normal API. The UI exposes edit history only while the message remains live. Built, and its migration is applied to Supabase as of 1 September; the browser flow is still unverified.
Real-time delivery and notificationsBuiltMigration 0016. Supabase Realtime invalidates RLS-protected server views for new messages, edits and retractions without polling. Durable in-app notifications are limited to mentions and replies, copy no message content, collapse a reply-plus-mention into one item, link to the retained message and disappear with conversation access. Read receipts advance only through the last rendered message, closing a race that could mark an unseen concurrent arrival as read. Built and tested, and migrations 0010–0016 are applied as of 1 September; the live socket flow remains browser-unverified. An opt-in email digest remains a later external-provider enhancement.
Offline access (requested and designed 20 August; production code complete, migration 0017 applied 1 September — full spec in Documentation/OFFLINE_ACCESS.md)
Close to load-bearing for adoption, not a convenience. AIC is in Accra: patchy connectivity and power cuts are not edge cases, and a document platform that cannot be read on a bad connection is one people work around. The workaround is WhatsApp, which is the thing this project exists to replace.

It collides with the permission model, and the collision resolves. An offline file sits outside access control — revoking does not remove it and the audit trail stops. But the Download button already exists: today a dropped connection means somebody puts a permanent, invisible, uncontrolled copy on their disk. A managed cache with a lease, revocation and a record is strictly more controlled than what already happens. This is not a loosening of the model; it is a better-behaved alternative to something people already do.
Mark a document available offlineBuiltAny current reader may request a managed copy unless the owner disables it. Migration 0017 protects the veto with an owner-only trigger and serializes grants against concurrent vetoes. The route rechecks RLS before issuing a five-minute signed URL.
Cached reading with a 30-day leaseBuiltDocument bytes live in per-browser IndexedDB, not the service-worker cache or Downloads. The server authors and renews a 30-day per-user/per-device lease; expired copies are purged before display. Browser storage is not presented as encrypted or as protection from someone controlling the same browser profile.
Revocation and purgeBuiltReconnect batch-revalidates every lease and removes copies after permission loss, owner veto or expiry. Sign-out clears cached documents and queued uploads. A disconnected device can retain a revoked copy until reconnect or lease expiry; that unavoidable limit is stated in the UI and specification.
Offline upload queueBuiltEvery selected file is persisted before network work, uploads sequentially, records each completed stage, resumes on reconnect and finalizes idempotently. One failed file does not discard successful files or duplicate an already-recorded document.
Offline audit recordBuiltoffline_document_leases records first/latest grant, validation, expiry, revocation reason and grant count. Authenticated clients cannot forge, update or delete audit rows; writes pass through caller-checking RPCs. Built and statically tested, not yet executed or deployed.
Installable as a PWABuiltA web manifest and narrowly scoped service worker cache only the offline shell and immutable framework assets. Authenticated HTML, APIs and signed document URLs are explicitly excluded; document bytes remain in the lease-aware IndexedDB store.

Roles & Team (requested 20 Aug) — specified in Documentation/ROLE_MODEL.md
Document roles: Viewer / Editor / OwnerBuiltMigration 0007. document_access.role as an ordered enum, plus can_comment_on_document and can_edit_document. Every existing grant became Viewer, so nobody's access changed on the day it shipped. Sharing panel picks a role when sharing and changes it afterwards, submitting on change rather than behind a Save button people forget to press.
Document role: CommenterBuiltComments exist. document_comments with threaded replies via parent_id, at document level or anchored to a page. The passage is stored as text rather than a character offset — an offset breaks the moment an editor replaces the file, silently, pointing at the wrong text, which is worse than pointing at nothing. Authors are on delete set null: a departed colleague's comments stay, because a thread with half its turns removed reads as though the rest were answering nobody.
Role-aware permission helpersBuiltcan_read_document lost its administrator clause and can_manage_document kept one — that pair is the “manage access but do not read” decision, centralized in two functions rather than repeated across policies. The RAG layer needed no permission filter: the database decision propagated to retrieval, download and Ask.
People page: person detail viewBuilt/admin/people/[userId]. Their platform role, everything they own, everything shared with them and at what role. Legacy /admin/team links redirect permanently. Bounded by what the caller may see — an administrator gets the whole who-can-reach-what picture without gaining the ability to read any of it.
Last-administrator protectionBuiltA before update trigger on profiles, not a UI check, so it holds whichever code path attempts it. Fires on demotion and on deactivation — both are ways to reach zero administrators, and only one of them was obvious.
Comment on a selected passage in the previewBuiltPDF readers can switch from the visual preview to a selectable, permission-checked text view, select text within one page, and have page plus quote populate the existing comment form. Extraction uses the already-installed PDF parser in a separate non-RAG module. Scanned PDFs honestly report that OCR is required.
Departure handlingBuiltDeactivate, not delete. profiles.deactivated_at ends sign-in — enforced in the session check as well as at the provider, so an existing token dies at its next request rather than lingering. Documents, grants and comments are untouched and it is reversible. Ownership transfer is a separate deliberate act on the person detail view, because the right new owner is a judgement about the work rather than about the org chart.

Documents in context, and team messaging (requested 21 Aug)
Contextual embeddingsBuiltThe change that makes retrieval understand what a document is. Chunking destroys a passage's place in the whole: “the fee is GHS 500” names neither the programme nor the year, so its embedding sits nowhere near the question it answers, and the keyword arm cannot help because the two share almost no words. Each chunk is now embedded together with its document's title, tags, summary and page. The header lives in its own column and never enters content — a citation quotes the document, not a preamble this code wrote. It costs no extra model call: the textbook version asks a model per chunk, which multiplies ingestion cost by the chunk count. Ingestion now summarises before embedding, because the summary is an input to the header.
Team messagingBuiltMigrations 0008, 0011 and 0012. One store supports strict two-person Direct messages and governed open/closed Teams, with unread state, replies, mentions, reactions, edit history and retraction. Direct creation is race-safe; Team membership changes are explicit and permission checked.
Messages as a retrieval sourceBuiltAsk can ground an answer in accessible group messages, not only documents. Direct messages are excluded by migration 0009. Retrieval runs through SECURITY INVOKER functions, uses fewer passages and a higher similarity floor than documents, ranks messages second and cites them differently with attribution in the prose.
Permission boundary for messagingBuiltProven, not asserted. Seventeen assertions added to npm run verify:rls:local, run against a real Postgres 16 with pgvector: a participant reads the thread and retrieves from it; an outsider sees no thread, no participants, no messages and gets nothing from search_chat_messages; three writes are refused — posting into someone else's thread, adding yourself to one, and signing another person's name to a message. An administrator who is not a participant sees nothing at all, which is the assertion that says out loud what migration 0007 started.
Portable schema keeps upBuiltThe schema-parity test caught all three new tables missing from db/portable-schema.sql and refused to pass until they were added — which is the guard rail working. The portable copy now applies cleanly to a plain Postgres with every chat table, policy and function present, so Bishop's “must port from one database to the next” still holds with messaging in it.

Getting it online (requested 26 Aug)
Function duration ceilingBuiltNeither long-running route said how long it was allowed to take, so the host picked its own default. On a serverless platform that default is short. /api/rag/ask streams a generated answer a token at a time over one connection; /api/documents runs extraction and embedding inside after(), which inherits the same ceiling. Both now declare maxDuration = 60, the maximum a Vercel Hobby project allows, and the value is confirmed present in the build output Vercel reads (functions-config-manifest.json). The failure this prevents is the quiet one: an answer cut off mid-sentence reads as an answer that simply stopped, and a half-embedded document reports as a parse failure rather than a timeout.
Vercel walkthroughBuiltDocumentation/VERCEL_SETUP.md. Written to the agreed assume-no-prior-knowledge standard. It explains the Vercel/Supabase split, build-time public variables, redeployment requirements and ends with a second-account restricted-document denial check.
Environment errors that say where to fix themBuiltA missing variable used to advise copying .env.example to .env.local — correct locally, useless to somebody reading a Vercel log. The message now names both places, and for a NEXT_PUBLIC_ variable adds that the value is baked in at build time and a redeploy is required. Small change; it is the difference between a five-minute fix and an afternoon.
